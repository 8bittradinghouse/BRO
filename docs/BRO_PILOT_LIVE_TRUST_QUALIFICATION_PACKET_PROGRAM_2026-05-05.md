## Shared Packet Structure
Every packet must produce these sections:

1. `Authority Lock`
- current pickup point
- authority chain
- no-change list
- blocker being judged

2. `Self-Hardening Gate`
- mission lock
- doctrine lock
- authority lock
- pathology lock
- semantic lock
- timing lock
- economic-meaning lock
- false-closure list
- `GO / NO-GO`

3. `Module Intake`
- authoritative sources
- runtime artifacts
- validators / gates
- reports / operator surfaces
- stale surfaces that must not dominate judgment

4. `Forward Semantics Sweep`
- doctrine -> config -> runtime emitter -> validator/gate -> report ->
  board/operator doc
- prove the same concept keeps the same meaning end to end

5. `Reverse Semantics Sweep`
- board/operator claim -> report -> validator/gate -> runtime emitter ->
  doctrine
- prove every front-door claim can be walked backward to the true owner

6. `Contradiction Compression Pass`
- force the packet to answer, in one compressed map:
  - who owns this truth
  - what surface is pretending to own it but should not
  - what stronger authority could still be replaced by a weaker convenience
    surface
  - what the real disease is in one sentence
  - what absolutely must not change while fixing it

7. `Negative-Proof Pass`
- spend an explicit pass trying to disprove the preferred diagnosis or closure
  story
- ask:
  - what evidence would falsify this conclusion
  - what nearby artifact or gate would most likely contradict it
  - what weaker explanation am I accidentally accepting because it is tidy
  - what untested assumption would turn this into false closure

8. `Combat Timing Doctrine Verification`
- host -> runtime -> weapon/wallet -> validators -> reports
- reports -> validators -> runtime -> host
- include host-out-and-back combat timing check

9. `Gate Legitimacy Sweep`
- each relevant gate must record:
  - owner
  - inputs
  - decision it is allowed to make
  - fail-closed / fail-open posture
  - dependent upstream truths
  - stale/ghost-path risk
  - whether current behavior actually matches doctrine

10. `Dependency Review`
- upstream pollution risk
- downstream blast radius
- false-closure risk
- no-shortcut zones

11. `Binary Verdict`
- `Bounded-live-test ready`
- or `Needs work`

12. `Closure Matrix Update`
- what must become true
- required proof artifact
- currently missing proof

## Stop-The-Line Triggers
A packet must pause and reclassify if any appear:
- doctrine and runtime disagree on the lane’s basic meaning
- wallet authority and weapon authority use the same words for different truths
- host timing is degraded while downstream weapon/wallet claims are being made
- the packet starts tuning before proving trust
- `prelive_gate` / `live_canary` green is being spoken about like final live
  trust
- contradiction compression still shows a shadow owner or a weaker surface
  impersonating a stronger one
- the negative-proof pass still has an easy falsifier the packet has not faced
- metrics look good but capital-safety semantics look weak
- semantics look clean but the weapon has no credible economic trust evidence
- a weaker gate/report/readout is being used to replace a stronger existing
  authority surface
