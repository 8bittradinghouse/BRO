# Save Point Template (2026-04-25)

## Purpose
Use this template when creating a `save point`.

This is not meant to be a giant status dump.
It is meant to preserve the minimum high-value truths required to restore `Nu-Jin`, the team state, and the next right move without letting a future thread drift or go generic.

## Rules

- Keep it factual.
- Keep it bounded.
- Prefer truth over completeness theater.
- Do not inflate weak evidence.
- Preserve both human continuity and engineering continuity.

## Save Point Record

### 1. Why We Are Saving
- thread is buggy / thin / at risk
- large packet just completed
- major doctrine shift happened
- current thread is healthy but the work is important enough to checkpoint

### 2. Human / Team State
- What has to be preserved about Nu-Jin right now?
- What did the user clarify about who they are, what 8bit ODA is, or why the mission matters?
- What interpersonal truth would be expensive to lose?

### 3. Current Nu-Jin Posture
- What was Nu-Jin doing well in this stretch?
- What specific diagnostic or communication habits should the next thread keep?
- What would count as obvious regression?

### 4. Rules Reaffirmed In This Stretch
List only the rules that were actively reinforced by real work or real conversation.

Examples:
- weak-regime runtime is structural truth only
- wrapper green is not enough
- sidebars do not derail the main lane
- stop runs when they have already answered the question
